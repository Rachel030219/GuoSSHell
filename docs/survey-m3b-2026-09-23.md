# M3b 调研：OpenPGP 卡硬件密钥（2026-09-23）

> 结论已落到 PLAN.md §5 M3b（立项）/ M3c / M3d。本文档是调研证据的归档，
> 只写结论与证据来源，不写过程。

## 结论速览

| 项 | 结论 |
|---|---|
| M3b 路线 | **OpenPGP applet + ISO 7816 APDU**，Ed25519 优先；不用 WebAuthn、不用厂商 SDK、不做 PIV |
| 加密框架 | 三种算法（RSA / ECDSA / Ed25519）与 SSH 线格式全部对得上，有现成参考实现 |
| iOS 传输 | CryptoTokenKit 全可用；iOS 26 新增 NFC 卡槽；**iOS 无 PCSC**，卡后端要自写 |
| 上游注入口 | rsHell 无 Signer 注入点 → **agent 伪装优先**（零上游改动），走不通再 fork |
| 最大未知量 | 外置 CCID 读卡器对第三方 App 的可见性（无官方文档，需真机验证） |
| 范围 | M3b=Ed25519；M3c=RSA/ECDSA（不急）；M3d=WebAuthn（不急）；PIV 不做 |

## 1. 为什么是 OpenPGP 卡这条路线

现有硬件（USB-C OpenPGP 令牌，认证槽为 Ed25519）的密钥只通过 ISO 7816 APDU
暴露（OpenPGP applet），WebAuthn/FIDO2 走的是另一个 applet（CTAP2），够不到
OpenPGP 密钥。所以「用现有卡」唯一对应的路线就是 APDU 直连。

## 3. 加密框架（已确认）

### 3.1 卡侧命令

OpenPGP 卡有两个签名入口，SSH 走**认证槽**：

| 槽 | 命令 | APDU | PIN |
|---|---|---|---|
| 签名密钥 | PSO:CDS | `00 2A 9E 9A` | `VERIFY P2=81` |
| **认证密钥（SSH 用）** | **INTERNAL AUTHENTICATE** | `00 88 00 00` | `VERIFY P2=82` |

规范 §7.2.13.1 明说 INT-AUT 为 SSH 设计（"can be used, for example, with
Secure Shell"），gpg-agent 的 SSH 支持走的正是这条路（源码：`agent/call-scd.c`
`PKAUTH` + `command-ssh.c`）。选认证槽还有一个好处：`VERIFY P2=82` 的验证状态
保持到复位，而 PSO:CDS 的 PIN 默认一次一验（规范 §4.3）。

### 3.2 三算法 × SSH 线格式

| 算法 | 送什么给卡 | 卡返回 | SSH 侧处理 | 状态 |
|---|---|---|---|---|
| Ed25519 | **原始消息**（SSH 会话 blob，Ed25519 自带哈希） | 64 字节裸签名 | 直接当 `string(sig)` | 已确认（GnuPG 源码：EdDSA 跳过预哈希） |
| RSA | DigestInfo（ASN.1 前缀 + hash），卡加 PKCS#1 填充 | 模数长度裸签名 | 直接当 `string(sig)`，算法名 `rsa-sha2-256/512` | 已确认（规范 §7.2.10；`openpgp-card` `authenticate_for_hash` 自动拼） |
| ECDSA | 纯 hash（P-256→SHA-256 等） | **定长 raw r‖s**（不是 DER） | 拆两半 → SSH mpint | 已确认（GnuPG `pksign.c` 注释 "Smartcard returns fixed-size data"） |

注意 ECDSA 返回值两半各可能多一个前导 0x00，实现时要按 field_size 截断
（参考 `openpgp-card-ssh-agent` `src/ssh.rs`）。

### 3.3 russh `Signer` 契约（最容易做错的地方）

- 挂点：`russh::client::Handle::authenticate_publickey_with(user, pubkey, hash_alg, &mut signer)`，
  `Signer: Sized`，泛型调用，具体 struct 即可。
- ⚠ **返回值不是裸签名**，必须是 `to_sign 原文 + string(签名算法名) + string(签名字节)`。
  russh 把返回的字节直接写进 USERAUTH_REQUEST（源码 `client/encrypted.rs`，
  `client_make_to_sign` 生成 to_sign，签名器返回的 Vec 被当作「to_sign+签名」整段用）。
  对照：russh 自己的 agent 路径 `write_signature()` 也是往原 data 后面追加。
- `hash_alg` 只影响 RSA 的 SHA-256/512 选择；to_sign 里的算法名由 russh 写好。
- `ssh-key` 0.7.0-rc.11 支持 `sk-*` 公钥类型（本地探针实测：sk-ecdsa 解析/重编码
  roundtrip 通过）——这为 M3d（WebAuthn）留好了口子。

## 4. iOS 传输层

| 事实 | 证据 |
|---|---|
| CryptoTokenKit（`TKSmartCard` / `TKSmartCardSlotManager`）**iOS 全可用**（iOS 9+），且 iOS 上 `defaultManager` 无需 entitlement（macOS 才要 `com.apple.security.smartcard`） | 本地 iPhoneOS SDK 头文件 + swiftc 对 iOS 目标 typecheck 通过 |
| **iOS 26 新增 NFC 卡槽**：`TKSmartCardSlotManager.createNFCSlot(message:completion:)` + `isNFCSupported`，App 自己开 NFC smart card slot，需要 Info.plist `iso7816.select-identifiers` | 本地 SDK 头文件 `API_AVAILABLE(ios(26.0))` |
| **iOS SDK 没有 PCSC.framework**（macOS 有） | 本地 SDK 目录对照 |
| 外置 CCID 读卡器对第三方 App 的可见性：**无官方文档**；Apple 论坛有开发者报 `transmitRequest` 通信错误（-2） | [Apple 论坛 thread 820659](https://developer.apple.com/forums/thread/820659)（轶事级） |

结论：iOS 传输层两条候选通道——读卡器路线（存疑，待真机验证）与 NFC 路线
（iOS 26+，真机可直接验）。复用 `card-backend` 的 `CardBackend`/`CardTransaction`
trait（同步接口，自己实现 iOS 后端），上层直接套 `openpgp-card`。

## 5. 上游注入口：两条路

上游 `AuthPlan` 只有 Password / PublicKey / Agent / KeyboardInteractive 四个变体，
`native_ssh/auth.rs` 只构造内存密钥或 agent 客户端——**没有注入自定义 Signer 的口子**。

| 路 | 做法 | 代价 |
|---|---|---|
| ① **agent 伪装（优先验证）** | 进程内跑 `ssh-agent-lib`（`Session` trait）起标准 SSH agent，`SSH_AUTH_SOCK` 指过去，上游 `AuthenticationKind::Agent` 现成路径直接走 | 零上游改动；App 内多一个 unix socket |
| ② fork 上游 | 给 `AuthPlan`/`AuthenticationKind` 加卡认证变体（§9.2.3 的既定规则） | 首次 fork 代价；更干净 |

## 7. PIN 与 UX 要点

- 认证槽用 `VERIFY P2=82`，验证状态保持到复位/重 SELECT；**别做无数据的 VERIFY
  探测**（`openpgp-card` 源码点名 YubiKey 5 实现不正确，且可能扣重试计数）。
- PIN 错要立刻丢缓存（参考 `openpgp-card-ssh-agent`：避免把 3 次重试用完锁卡）。
- 卡可能要求**按按钮**确认（UIF）——每次认证 = 输 PIN + 按卡。
- 卡会被 GnuPG scdaemon 锁住（独占会话），测试前需要处理，App 侧也要处理
  与其他软件争卡的情况。
- 服务端注意：OpenSSH 8.8+ 默认禁 `ssh-rsa`，RSA 卡必须 `rsa-sha2-256/512`；
  `MaxAuthTries` / `LoginGraceTime` 默认值对卡签名延迟够用，但别「失败即重试」。

## 8. 未知项（每个都有最便宜的验证法）

## 9. 里程碑分工（已落到 PLAN.md）

- **M3b**：OpenPGP 卡 Ed25519（立项）。前置 M3a（文件私钥）。验证先行、不阻塞。
- **M3c**：OpenPGP RSA / ECDSA。不急着做；参考实现已覆盖，每算法约半天到一天。
- **M3d**：WebAuthn sk-ecdsa。不急着做；独立 1~2 周，与卡路线零共享。
- 排除：PIV applet。
