# 帧里的 selected 位暂未消费

- 状态：已知、不修（记录设计现状，M4 可能启用）
- 记录日期：2026-09-24

## 现状

选区高亮由 fork 画（`RenderTerminal._paintSelection`，数据来自引擎回显的
纯坐标选区），帧压缩格式里引擎逐格标记的 `selected` 位（`frame_codec.rs`
attrs 第 5 位、Dart 侧 `Attr.selected`）因此**无人消费**。wire 格式里保留它
没有成本——`same_run` 已把 selected 计入 run 边界，位宽也不变。

## 下一步

M4 做滚回时，若选区需要跨越「不在视口内的行」（纯坐标投影对画不出耳
朵的行只能贴边截断），可改由帧的 `selected` 位直接驱动高亮（App 逐格换
底色，fork 关掉自己的选区填充）。届时再决定两条路的取舍，目前不动。
